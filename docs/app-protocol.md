# 报文分析 APP 接口契约（v1.1）

> 本文档是手机 APP 与 ESP32 固件之间的唯一接口依据，两边各自开发，只靠这份契约对齐。
> APP 侧新会话开工时，以本文档为准，不需要继承固件会话的对话历史。

## 1. 系统角色

```
485 总线 ←→ BT04E(从机) ←→ [ESP32 主机/中继] ←→ [手机 APP]
                ↑________________直接连接_________↑
                    （同一时间 BT04E 只能被一个主机连）
```

- **ESP32**：蓝牙中继（收报文上屏 + 转发手机）、TF 卡报文落盘、按规则实时解码显示、接收 APP 下发的规则
- **APP**：连蓝牙收报文、AI 分析、编写协议规则、下发规则给 ESP32
- **ESP32 侧 AI 分析**：搁置为后续计划

## 2. 两种连接模式（APP 都要支持，做成两个入口）

### 模式 A：直连 BT04E（纯透传，分析用）

| 项 | 值 |
|---|---|
| 服务 | `FFE0` |
| 收（notify） | `FFE1` —— 模块转发的 485 原始字节 |
| 发（write） | `FFE2` —— 写入即上 485 总线 |

- BT04E 名称前缀默认 `BT04E`（可被 AT+NAME 改过）
- 有主机已连接时不响应 AT 命令；一次写入建议 ≤20 字节（模块串口波特率决定吞吐）

### 模式 B：连 ESP32（中继 + 控制，分析/运行两用）

| 项 | 值 |
|---|---|
| 服务（NUS） | `6e400001-b5a3-f393-e0a9-e50e24dcca9e` |
| 收（notify） | `6e400003-...cca9e` —— 报文/解析事件/命令响应，混流 |
| 发（write，无响应写即可） | `6e400002-...cca9e` —— 报文与命令 |
| MTU | 请求到 247；单次 write ≤244 字节，ESP32 自动分片 |
| 设备名 | `ESP32-S3-AI`（NVS 可改） |

**通道复用规则**：NUS 上跑两类数据——
1. **透传字节**：485 原始报文原样转发（ESP32 不加帧头，**无帧边界保证**，APP 自行按协议切帧；注意：以 `{` 开头的透传字节会被当作控制行起点，避免发送此类数据）
2. **控制行**：以 `{` 开头、`\n` 结尾的单行 JSON 命令/事件。APP 发送侧注意：**命令 ≤244 字节时一次 write；更长的命令（如 rule.set 大规则）分多次 write 连续发送**，每片 ≤244 字节，最后一片以 `\n` 结尾即可——ESP32 支持跨包拼行（单条上限 8KB，收到 `\n` 才执行）。分片必须连续发送（片间隔 <500ms），否则半截行会被当作无效数据放行。解析时只把以 `{` 开头且 `\n` 结尾的片段当控制行，其余都是透传字节

## 3. 控制行协议（模式 B）

请求：`{"cmd":"...", ...}\n`（长命令可分多次 write 连续发送，见第 2 节通道复用规则）；响应：`{"rsp":"...", ...}\n`；事件：`{"evt":"...", ...}\n`

| 命令 | 响应/事件 | 说明 |
|---|---|---|
| `{"cmd":"info"}` | `{"rsp":"info","fw":"1.3.1","relay":true,"conn":true,"rule":"电表03","log":true}` | 握手/查状态 |
| `{"cmd":"rule.set","rule":{...}}` | `{"rsp":"ok"}` / `{"rsp":"err","why":"..."}` | 下发规则，存 `/rules/<name>.json` 并立即生效 |
| `{"cmd":"rule.list"}` | `{"rsp":"rule.list","names":["电表03","..."]}` | 规则列表 |
| `{"cmd":"rule.get","name":"电表03"}` | `{"rsp":"rule.get","rule":{...}}` | 读回规则 |
| `{"cmd":"rule.del","name":"..."}` | `{"rsp":"ok"}` | 删除规则 |
| `{"cmd":"log.stop"}` / `{"cmd":"log.start"}` | `{"rsp":"ok","session":"log_1103_1432"}` | 手动停止/重新开始落盘会话 |
| `{"cmd":"dec.on"}` / `{"cmd":"dec.off"}` | `{"rsp":"ok"}` | 开关解析事件推送 |
| `{"cmd":"sim.on"}` / `{"cmd":"sim.off"}` | `{"rsp":"ok"}` | 开关内置模拟开关量帧（见第 9 节，联调测试用） |
| `{"cmd":"yk","name":"远程合闸","dev":1}` | `{"rsp":"ok","yk":"远程合闸","dev":1,"frame":"010500 00FF 00..."}` / `{"rsp":"err","why":"..."}` | 遥控下发（v1.1，见第 10 节，ESP32 侧待实现） |
| `{"cmd":"te.on"}` / `{"cmd":"te.off"}` | `{"rsp":"ok"}` | 开关内置模拟遥测帧（见第 9 节，联调测试用） |

事件（规则生效且 dec.on 时，每解析一帧推一行）：

```json
{"evt":"dec","t":49812345,"rule":"电表03","dev":1,"vals":["220.5","1.23","OK"]}
```
vals 顺序与规则 fields 一致；无法解析的字段填 `null`；多设备规则带 `dev`（设备地址），单设备规则不带。

## 4. 规则 JSON Schema（v1.1，含多设备 / 告警阈值 / 遥控）

```json
{
  "name": "电表03",            // 规则名，唯一，即文件名
  "ver": 1,                    // 版本，每次修改 +1
  "src": "AI会话2026-11-03",   // 来源备注
  "addr": {"off": 0, "type": "u8"},   // 多设备：从帧里哪个字节取设备地址（省略=单设备）
  "match": [{"off": 0, "val": [1, 2]}],  // 可选：字节命中才解析（总线混有其他帧时防乱解）
  "crc": "modbus",             // 可选：CRC 校验通过的帧才解析（v2 实现，先预留）；yk 组帧时也按此补 CRC
  "fields": [                  // 最多 64 个字段（ESP32 侧限制，超出 rule.set 返回 too many fields）
    {
      "name": "电压",           // 字段名
      "off": 3,                // 帧内字节偏移（0 起，含帧头）
      "type": "u16",           // u8/i8/u16/i16/u32/i32/f32/bit
      "be": 1,                 // 1=大端 0=小端（u16/u32 有效）
      "bit": 3,                // 仅 type=bit：位偏移 0-7
      "scale": 0.1,            // 原始值 × scale（可省，省=1）
      "unit": "V",             // 单位（可省）
      "enum": {"1":"合","0":"分"},  // 枚举映射（可省，命中则显示映射文本）
      "limit": {"min": 198, "max": 242}  // v1.1 可选：正常范围，超限用于告警着色（仅展示，不影响解析）
    }
  ],
  "yks": [                     // v1.1 可选：遥控项（见第 10 节）
    {"name": "远程合闸", "dev": 1, "bytes": "XX 05 00 00 FF 00", "crc": "modbus", "confirm": true}
  ]
}
```

多设备语义：
- 有 `addr` 时，解析引擎先读出设备地址，把解析结果归到该设备名下；各设备独立维护当前值；所有设备共用同一份 `fields`（同型号设备，最常见场景）
- 异构布局（每台设备字段不同）预留 `devs:{"1":[...],"2":[...]}` 替代 `fields`，v2 实现
- 事件与显示按设备分组；`evt:dec` 带 `"dev":<地址>`（单设备规则不带 dev 字段）

解析规则：ESP32/APP 收到报文后：match 命中（若有）→ 读 addr（若有）→ 按 fields 逐个取字节 → 按类型/字节序/位 → 乘 scale → 命中 enum 显示文本，否则数值+unit。两端逐字段语义必须一致。

## 5. 报文编码

- 透传字节永远是原始字节，ESP32 不改编码（GBK/UTF-8 转换只发生在 ESP32 的屏幕显示侧）
- APP 显示文本时按自身编码设置处理，hex 视图始终可用

## 6. 固件侧现状（APP 联调时参考）

- 仓库：`f:\ESP32\esp32s3`（GitHub: esp32-s3-ai-player / esp32s3-ai-chat），固件源码 `esp32/esp32_ai_chat/`
- OTA 推送：`POST firmware.bin → http://<设备IP>:8080/ota`；网页控制台 `http://<设备IP>:8080/`
- TF 卡落盘：`/logs/<会话>/frames.jsonl`（每帧一行 `{"t":ms,"rx":0/1,"len":n,"hex":"AA BB"}`）、`/logs/<会话>/decoded.csv`（开关）、`/rules/<名称>.json`、`/ai/<会话>.jsonl`
- 会话自动开/收尾：中继连上自动开，断开收尾；单文件 2MB 分卷

## 7. APP 侧待定项（新会话先定）

1. 技术栈：Android 原生 / Flutter / 其他（需要 BLE central + 后台收发，小程序 BLE 限制多，慎选）

## 8. APP 内置规则解析器（必备能力，用于下发前调试）

APP 必须按第 4 节同一份 Schema **本地实现规则解析**，与 ESP32 逐字段语义一致（偏移/类型/字节序/位/缩放/枚举）。用途：

1. **生成即验证**：AI 生成规则草稿后，APP 对「刚收到的最近 N 帧报文」立即按草稿解析，用户在手机上直接看到解析值是否合理（数值范围、单位、枚举命中），确认无误再 `rule.set` 下发——不必先下发到 ESP32 再试错
2. **两端一致性比对**：规则下发后 ESP32 会推 `{"evt":"dec",...}` 事件，APP 把事件值与自己本地解析值比对，不一致说明规则有歧义或某端实现有偏差，当场暴露
3. **离线调试**：直连 BT04E 模式（模式 A）下 ESP32 不参与，APP 本地解析就是唯一的实时解码视图

调试视图建议：hex 原文 + 每个字段的高亮字节区间（off..off+len）+ 解析值列表，一眼对上「哪几个字节解析成了哪个值」。

## 9. 内置模拟测试帧（联调辅助）

固件可周期生成模拟报文，用于 APP 端 AI 分析与规则解析的全链路联调（不需要真实 485 设备）。两种帧独立开关，均走真实链路——手机收到透传字节（NUS notify）、ESP32 上屏/落盘 frames.jsonl、若激活规则则正常解码并推 `evt:dec`。

- **开关量帧**：`sim.on`/`sim.off` 命令，或屏幕 配置项 → 协议解码 → 「模拟开关量 >」进入按钮页开启
- **遥测帧**：`te.on`/`te.off` 命令，或「模拟遥测 >」页开启
- **频率**：各每 1.5 秒一帧

### 9.1 开关量帧（可配路数/模式/状态）

Modbus RTU 读线圈应答风格，参数（配置项页或屏幕「模拟开关量」页可改，改动即时生效）：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `开关路数` | 8 | 1~64 路；byteCount = (路数+7)/8 |
| `开关模式` | 随机 | 随机=每帧在当前位图上随机翻转 0~2 路（贴近真实开关动作）；固定=每帧发当前位图原样 |
| `开关位图(hex)` | 01 | 高字节在前，bit0=路1。如 `DD`=8路中 路2/路6 关；`8001`=16路中 路1/路16 开 |

**屏幕路按钮页**（配置项 → 模拟开关量 >）：每路一个按钮，点击切换开/关，与位图 hex 双向同步（按钮改动写回 `开关位图(hex)` 配置项），最多 64 路一屏放完。固定模式下位图就是发帧内容；随机模式下位图是翻转的起点。

帧格式（6~13 字节，真实 CRC16）：

```
01              设备地址
03              功能码（读线圈）
NN              字节数 = (路数+7)/8
XX ...          状态位图，高字节在前（bit0=路1，1=开 0=关）
LO HI           CRC16-Modbus（低字节在前）
```

示例（8 路，`DD` 位图）：`01 03 01 DD 30 11` → 路1 开、路2 关、路3~路5 开、路6 关、路7~路8 开

### 9.2 遥测帧（可配通道数/基准值的模拟量）

Modbus RTU 读输入寄存器应答（功能码 04），参数（配置项页或屏幕「模拟遥测」页可改）：

| 配置项 | 默认 | 说明 |
|---|---|---|
| `遥测通道数` | 4 | 1~8 通道；字节数 = 2×N |
| `遥测基准1~8` | 2200/123/2500/265/... | 每通道发送基准值（0~65535），波动 = 基准 ±1%（至少 ±1） |

默认 4 通道对应：电压（0.1V ≈ 218~222V）、电流（0.1A ≈ 11~13.5A）、功率（1W ≈ 2420~2580W）、温度（0.1℃ ≈ 26.1~26.9℃）。

帧格式（7~21 字节，随通道数变化，真实 CRC16）：

```
01              设备地址
04              功能码（读输入寄存器）
NN              字节数 = 2×通道数
R0H R0L         通道0，u16 大端（基准值±波动）
...             依次各通道
LO HI           CRC16-Modbus（低字节在前）
```

### 示例规则（可直接 rule.set 下发验证解析链路）

开关量（8 路 bit + 枚举）：

```json
{"name":"模拟开关量","ver":1,"src":"固件内置模拟","match":[{"off":0,"val":[1]},{"off":1,"val":[3]},{"off":2,"val":[1]}],"fields":[{"name":"D1","off":3,"type":"bit","bit":0,"enum":{"1":"开","0":"关"}},{"name":"D2","off":3,"type":"bit","bit":1,"enum":{"1":"开","0":"关"}},{"name":"D3","off":3,"type":"bit","bit":2,"enum":{"1":"开","0":"关"}},{"name":"D4","off":3,"type":"bit","bit":3,"enum":{"1":"开","0":"关"}},{"name":"D5","off":3,"type":"bit","bit":4,"enum":{"1":"开","0":"关"}},{"name":"D6","off":3,"type":"bit","bit":5,"enum":{"1":"开","0":"关"}},{"name":"D7","off":3,"type":"bit","bit":6,"enum":{"1":"开","0":"关"}},{"name":"D8","off":3,"type":"bit","bit":7,"enum":{"1":"开","0":"关"}}]}
```

遥测（4 通道模拟量）：

```json
{"name":"模拟遥测","ver":1,"src":"固件内置模拟","match":[{"off":0,"val":[1]},{"off":1,"val":[4]},{"off":2,"val":[8]}],"fields":[{"name":"电压","off":3,"type":"u16","be":1,"scale":0.1,"unit":"V"},{"name":"电流","off":5,"type":"u16","be":1,"scale":0.1,"unit":"A"},{"name":"功率","off":7,"type":"u16","be":1,"scale":1,"unit":"W"},{"name":"温度","off":9,"type":"u16","be":1,"scale":0.1,"unit":"℃"}]}
```

**联调建议流程**：`sim.on`（或 `te.on`）→ APP 收到报文做 AI 分析（应识别出 Modbus 线圈/寄存器应答）→ APP 本地按上述规则解析最近帧验证 → `rule.set` 下发 → `dec.on` → ESP32 推 `evt:dec` → APP 比对本地解析与 evt 值应一致 → 测完 `sim.off` / `te.off`。

## 10. 遥控（YK，v1.1 新增）

遥控 = APP 经 ESP32 中继向 485 总线下发控制帧（如写线圈分合闸）。规则里用可选 `yks` 数组描述遥控项，两端共用同一份模板组帧语义。

### 10.1 规则中的遥控项（Schema 见第 4 节 yks）

```json
{
  "name": "远程合闸",                 // 按钮名，规则内唯一
  "dev": 1,                          // 目标设备地址；有 addr 的规则建议填，用于校验与显示
  "bytes": "XX 05 00 00 FF 00",      // 帧模板 hex，空格分隔，见占位符规则
  "crc": "modbus",                   // 可选，默认取规则根的 crc 字段；组帧时在帧尾自动补 CRC
  "confirm": true                    // 可选，默认 true：APP 下发前弹二次确认
}
```

**帧模板占位符**（组帧时替换）：

| 占位符 | 含义 |
|---|---|
| `XX`（不区分大小写） | 替换为下发命令里的 `dev` 地址；无 `dev` 时替换为 `01` |
| 其余 | 按两位 hex 原样取用 |

**组帧顺序**：替换占位符 → 若 crc 类型为 `modbus`（其他值 v2 再扩展），对模板全字节计算 CRC16-Modbus 并以 `LO HI` 追加帧尾。示例：模板 `XX 05 00 00 FF 00` + dev=1 → 发出 `01 05 00 00 FF 00 <CRC_LO> <CRC_HI>`。

### 10.2 下发命令与响应

```json
{"cmd":"yk","name":"远程合闸","dev":1}\n
```

- ESP32 在**当前生效规则**里查 `yks`：名字必须精确匹配；命令未带 `dev` 时取规则项里的 `dev`，两者都没有则 `{"rsp":"err","why":"缺少 dev"}`
- 找不到遥控项 → `{"rsp":"err","why":"未找到遥控项 远程合闸"}`
- 中继未连 485（`conn=false`）→ `{"rsp":"err","why":"485 未连接"}`
- 组帧后经中继写出（写出内容即 485 原始字节，与透传发送同一路径），成功返回：

```json
{"rsp":"ok","yk":"远程合闸","dev":1,"frame":"01050000FF008B3A"}
```

`frame` 为实际写出的完整帧 hex（含 CRC），供 APP 显示与日志核对。**`rsp:ok` 仅代表帧已发到 485 总线，不代表设备执行成功**；执行结果由 APP 侧通过后续遥信变位（SOE）或读回帧确认。ESP32 侧应把遥控写出帧按普通 TX 帧走原有链路（上屏/落盘 frames.jsonl/转发手机），无需新增记录结构。

### 10.3 过渡期兜底（ESP32 未实现 yk 时）

ESP32 对 `cmd:"yk"` 返回 `{"rsp":"err","why":...}` 即可（现有未知 cmd 处理已够用，不强求识别）。APP 在收到 err 后提供「透传直发」降级：APP 本地按 10.1 组帧，经 NUS 透传通道直接写出（ESP32 零改动）。降级方式没有遥控日志与规则校验，仅用于临时联调。

### 10.4 APP 侧交互约定

- 遥控按钮只在**激活规则含 yks** 且连接就绪时显示；多设备规则按当前选中设备过滤 `dev`
- `confirm:true`（默认）的项下发前弹确认框，明确显示：按钮名、目标设备、组帧后的完整帧 hex
- 下发成功（rsp:ok）后在变位记录区标注「已发出，待变位确认」；收到后续 `evt:dec` 中对应遥信变化时在 SOE 里与该次遥控关联展示
